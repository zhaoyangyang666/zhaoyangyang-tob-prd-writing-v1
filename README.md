# zhaoyangyang-tob-prd-writing-v1

一个面向 **B 端产品需求文档（PRD）** 写作的 AI 技能（Skill）：按真实产品经理的工作风格产出**研发可直接落地**的结构化 PRD。

## 产出特点

- **结构按端组织**：运营端 / 企业端 / 资金方端……端内按模块 → 页面展开
- **字段表精确到组件与校验规则**：控件类型、必填、格式要求、最大长度、联动规则逐列写清
- **异常分支全覆盖**：每个功能至少覆盖 1~2 个异常分支，提示文案给出研发可复制的中文原文
- **状态枚举 + 各端操作**：状态流转逐个列出，判定条件与恢复方式成表
- **决策附理由**：关键规则（扣费时点、兜底策略等）附带"为什么这样定"
- **不臆测**：未确认的信息一律标【待确认】，定稿前闭环消项

## 目录结构

```
├── SKILL.md                     # 技能主文件：流程编排与硬性规则
└── references/

    └── excerpts.md              # 范例摘录：13 类段落的真实 PRD 写法（已脱敏）
```

## 工作流程

按需求规模分档，避免"小需求套大流程"：

1. **规模分档**：小需求（单页面/局部改动）问 1~2 个关键问题后一次成稿；中大需求（新系统/多端/计费权限类）走完整流程
2. **澄清关键决策**：本期范围、角色与端、核心规则、与现有系统的关系
3. **大纲确认**：章节大纲 + 每章一句话说明 + 【待确认】标注
4. **逐章起草**：每章一轮确认，"继续"即通过
5. **定稿交付**：待确认清单逐条闭环，输出单个 Markdown 文件

## 适用范围
